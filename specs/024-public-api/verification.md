# 024 Verification

Implemented: `src/PublicApi.php`, routing in `public/index.php` before `session_start`, `docs/api/openapi.json`, `templates/api-docs.html`.

Tested with curl against the development server: entry point 200 with `Link` to `service-desc` and `service-doc` and no `Set-Cookie`; product, specifications, relations (`kind=goes_with`), reviews, themes, one theme and specification keys return 200 JSON with `_links`; `q=hodelykt` returned 13 hits; `q=hammmer` reported `corrected: hammer`; `theme=lys&page=2&per_page=5` returned `X-Total-Count: 65` and links self, first, prev, next, last (last page 13); `sku=600461` returned one product. Errors: unknown product 404, `page=0` 400, `theme=xx` 400 with the allowed list, unknown path 404, `POST` and `DELETE` 405, `Accept: text/html` 406, all `application/problem+json`. `If-None-Match` with the ETag gave 304; `HEAD` 200 without body; `OPTIONS` 204 with `Allow`. `/api` redirects to `/api/docs` (301).

Run in the app (headless Chromium): `/api/docs` rendered 11 operation sections from the OpenAPI document; "Try it" on specifications showed 200 with headers and coloured JSON; "Send again with If-None-Match" showed 304 Not Modified; clicking a link in the JSON loaded that resource. At 390 px no horizontal scroll. PHPStan and unit tests pass.

Questions (`POST /api/v1/products/{id}/questions`), tested with curl on a second development server: `GET` 405 with `Allow: POST, OPTIONS`, `OPTIONS` 204, form body 415, empty question 400, a prompt injection got the fixed answer with `model.used: false` and no reasoning. Ollama was not reachable, so a battery question for a torch got the rule-based answer from its relations (GP AAA batteries, rule based) with the notice. Found and fixed: the first fallback was empty and listed unrelated products. Ten questions passed and the next got 429 with `Retry-After: 578`; the question log was cleared afterwards. The docs console sent the same question as POST with its JSON body and showed the answer.

With the language model (deepseek-r1:8b through Ollama): a battery question was answered through the API in 47 s with `model.used: true`. Found: the model wrote price and stock references with single brackets (`[lager:ID]`, `[pris:ID]`), which reached the answer as code, and through the plugin it wrote a link to a made-up shop address with a price in it. Fixed in `ProductRef::clean`, which the shop chat uses too: single-bracket references are read as references (checked against the facts, filled in from the database), Markdown links keep only their text and bare addresses are removed; regression test in `tests/ProductRefTest.php`. The same question afterwards had no references or links left and gave 3xAAA, 500 lm and 1.5 hours from the specifications. The reasoning was `null` both times: the model thought in English or Chinese, which is not shown for a Norwegian answer.

Known weakness: the model can still recommend a product that does not fit (it suggested a wick for a lantern next to the batteries) and has stated a value that contradicts the specifications (batteries not included). `products` lists the same cards as the shop chat, which can include unrelated products.

Not verified: a call from a real WooCommerce page on another domain (CORS headers are checked, not a cross-origin browser call); the OpenAPI document was not run through a validator.
