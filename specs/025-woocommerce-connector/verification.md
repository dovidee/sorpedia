# 025 Verification

Implemented: `src/WooSync.php`, the webhook route in `public/index.php`, `WC_WEBHOOK_SECRET` in `docker-compose.yml`, the plugin in `integrations/woocommerce/sorpedia-connector`, `docs/integration/woocommerce.md`.

Tested with curl against a second development server with a test secret: the ping body gave 200; a wrong signature 401; a signed `product.updated` for an existing product gave `updated` and kept its 11 specifications (8 from the store, 3 derived); the same delivery ID again gave `duplicate`; a signed `product.created` in a guide category created the product with battery, IP rating, brightness and use read from its text, and it was returned by `/api/v1/products/{id}`; `order.created` gave `ignored`; the server without a secret answered 503. The test product, its deliveries, its events and the specification keys only it used were removed afterwards, and the catalogue count was checked (496).

Plugin: `php -l` passes. WordPress is not installed here, so the hooks were run in a small harness that stands in for the WordPress and WooCommerce functions and calls the real API: the tab "Fakta og kilder" listed 11 values with "Bekreftet" or "Utledet fra produkttekst" and the five unknown filterable keys; "Passer sammen med" showed the AAA batteries as "Regelbasert" with the reason and the shop's link and price; a question through the REST route returned the answer with a Norwegian note that it came from the rules, and product links from the shop. With the API address pointing at a closed port, the tab, the relations and the question box were all left out.

Run in a real installation: WordPress 7.1.5 and WooCommerce 11.3.1 in throwaway containers on localhost, with the plugin mounted read-only and the API address set to the development server. WooCommerce 11 needs WordPress 7.0 or later; with 6.8 it refused to install. Without WooCommerce the plugin refused to activate (`Requires Plugins: woocommerce`). Two shop products were created with the guide's IDs (291445, 268745). The product page showed the tab "Fakta og kilder" with every value labelled "Bekreftet" or "Utledet fra produkttekst" and the five unknown keys, "Passer sammen med" with the AAA batteries as "Regelbasert", the reason and the shop's own name, price and link, and the question box; checked in a headless browser screenshot, with no PHP warnings in the page. A question through `/wp-json/sorpedia/v1/ask` was answered by the language model with reasoning (62 s measured). The first question, sent while the model was still loading, got the rule-based answer with the Norwegian note. The per visitor limit answered 429 with the Norwegian message on the sixth question within ten minutes.

Real webhooks: a webhook created in WooCommerce for `product.updated`, signed with a test secret, was delivered to a second development server pointing at an isolated copy of the database (`sorpedia_wctest`). The creation ping and the update both got 200, WooCommerce recorded no failures, and the copy took the shop's new name and price (259 kr) and kept the theme. A fingerprint of products 291445 and 268745 and their specification values in the real database was identical before and after.

Known weaknesses: an update from the shop rebuilds the store and derived specifications from the shop's own text, so a shop with a short description gives fewer values (5 instead of 11 in the test). A question about a product the API does not know was first passed on as 502; it now gives 404 with "Søren kjenner ikke dette produktet." (checked in the harness against the development server).

Found on the product page in the real shop: "Følger med: batterierDim" was shown as confirmed for 291445, although the text says the batteries are not included. Two causes in `Extract::specs`: "102gr inkl. batterier" (a weight) was read as the contents, and Sør-Tre's text runs fields together, so the next label ("Dim:") was glued on. The rule now skips "inkl." right after a weight or price and stops before a glued field label. Rerunning the rule over the whole catalogue changed only that product; its wrong value was removed from the database. Regression test in `tests/UsageTest.php`; tests and evals pass.

Not verified: the REST nonce (the route is public by design, the nonce is sent but not required); a shop on another host than the guide.
